# Pop-up facts (1.4.0)

Small speech-bubble facts that pop up during playback (composer, artists, premiere, critics, history, staging, bloopers, music).
**Every fact is real and sourced**: each one carries an `evidence` string that must appear verbatim in a cached copy of its source
(Wikipedia article, Met Opera Archives record, Met/press page). `verify.js` rejects anything whose evidence can't be found, and
`build.js` refuses to publish rejected facts. No invented quotes, reactions or bloopers.

## Layout

| Path | What |
|---|---|
| `titles/<slug>.json` | **Source of truth.** Curated facts per title (`match` = catalog titles, `facts[]` with `type`, `sceneMatch` regex against the Met scene markers or `null` for a general fact, `scope` (`all` or `production:YYYY-MM-DD`), `text`, `attribution`, `source`, `evidence`). |
| `titles/gen-<slug>.json` | Generated by `general.js`: up to two verbatim lead sentences (premiere, origin) from the opera's Wikipedia article for other catalog titles; used only when the article names the composer and calls the work an opera. |
| `t_*.py`, `mk.py` | The scripts the curated files were written with (kept for review). |
| `sources/` | Cached source texts used for verification (gitignored; re-fetch with `fetch-wiki.js` / `archive-src.js`). |
| `dist/` | Built, compact per-title files that are uploaded to the Worker (`build.js`). |

## Workflow

```sh
node facts/general.js        # optional: refresh general facts for other titles
node facts/build.js          # verify every fact, write dist/*.json + app/src/userscript/facts/factsData.js
node facts/deploy.js         # PUT dist/*.json to <MTV_WORKER_URL>/v1/facts/<slug>.json (needs READ_TOKEN in .env)
```

## Storage and delivery

* The repo JSON is the source of truth; the Worker serves `GET /v1/facts/<slug>.json` from a `facts` table in the
  **existing D1 database** that's already bound to the telemetry Worker, fronted by the Cache API (`max-age=86400`).
  Writes are `PUT` with the READ_TOKEN bearer.
* The app bundles the 10 most-watched titles (≈48 KB in the userscript, including the title index) so they work offline / instantly, and
  lazy-fetches the others once, caching them in localStorage for 7 days.
* Size: ≈137 KB for all 149 titles (278 curated + 204 general facts), 3–7 KB per curated title, 0.3–1 KB per general title. Requests: at most about 1 per non-bundled title per TV per week —
  far inside the free tiers (D1: 5 M row reads/day, 100 k writes/day, 5 GB; Workers: 100 k requests/day).
  KV would have needed a new namespace and has a 1 k writes/day free limit; R2 is unnecessary for ~140 KB.
